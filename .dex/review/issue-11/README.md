# Issue 11: deployment frequency and lead time

The [issue design comment](https://github.com/exmergo/github-repo-analytics/issues/11#issuecomment-6404591601) records the choices made before implementation. The initial implementation ran on Dex 1.15.2; the [runtime upgrade and final revalidation](dex-1.16.1/README.md) align the engine and lockfile with the intended Dex 1.16.1 skill upgrade. The initial evidence below remains historical. All analytics SQL, YAML, declarations and singular tests were written through Dex plans. Python collects and validates raw evidence; dbt selects shipping assignments and MetricFlow computes both aggregates.

## Decisions

- Opt-in GitHub Deployments with an explicit exact production environment; transient deployments excluded. Workflow runs, releases as deployment proxies, and first-commit lead time remain unsupported.
- Count each deployment ID once, at its earliest observed successful status. Redeployments count again when their IDs differ. Retain observed success across later inactive/failed statuses and API retention.
- Match PRs merged to the current default branch by merge-SHA containment, using identical SHAs or GitHub compare's ahead/identical status. Select the earliest observed successful containing deployment per repository/PR. Measure merge-to-success hours, with a continuous median over individual PRs, grouped by shipping date.
- Exclude the partial capture UTC day. Keep null lead time for deployments without mapped PRs. Missing observations stay unavailable. Listing completion does not establish complete historical coverage; status retention, deleted events and unknown earlier deployments remain limits.

## Validation and engine limits

The full suite passed **71 tests**, with **1 opt-in external live test skipped** ([test log](validation-tests.log)). Repository-wide Ruff lint and format checks also passed ([lint log](validation-lint.log)). Tests cover configuration, successful/inactive/failed statuses, exact environment selection, transient exclusion, commit ancestry, default-branch PRs, idempotent collection, historical retention, partial-list completeness, API failure atomicity, comparison limits, malformed/orphan/negative evidence, per-PR medians, redeployments, repository isolation, partial capture days and recipe refusals. The full suite also checks existing metrics and lifecycle failure behavior.

The installed skills describe newer `references --usage`, drafted declarations and commit-trailer output that the pinned 1.15.2 does not expose. No engine-returned commit trailer was present. Declaration splicing failed for indentless YAML sequences, so the proposal was re-authored with indented sequences and planned again; no guarded files were hand-edited. Detailed internal reproductions are retained in the unversioned `dex-field-reports/` directory.
